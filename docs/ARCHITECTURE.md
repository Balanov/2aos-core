# Архитектура 2AOS Core

## Цель

Локальный control plane, который принимает разрешённые данные компании, строит доказательную модель процессов, подбирает и устанавливает агентов, оркестрирует их совместную работу, считает фактическую эффективность и формирует приватные рыночные сигналы для разработчиков.

## Контур полного цикла

```text
Файлы / ERP / CRM / почта / телефония / датчики / события
                         │ scoped ingestion
                         ▼
          Бизнес-объекты + наблюдения + evidence
                         │
                         ▼
             ИИ-директор: проблема → baseline
                         │ локальный отбор
                         ▼
         Предложение агента → quote → approval → install
                         │
                         ▼
       DAG jobs + shared blackboard + артефакты + каналы
                         │
             ┌───────────┴────────────┐
             ▼                        ▼
     Метрики и ROI             Использование и ledger
             │                        │
             └───────────┬────────────┘
                         ▼
          Opt-in privacy gateway, k >= 5 tenants
                         │
                         ▼
      Агрегированный спрос → SDK и задания разработчикам
```

## Основные компоненты

- **HTTP API:** Node.js 24, REST/JSON, OpenAPI, bearer API keys, RBAC и tenant isolation.
- **SQLite:** WAL, foreign keys, транзакции, идемпотентные уникальные ключи, миграции.
- **Director:** evidence-linked observations, baseline cost, recommendations, pilot/stop conditions. Не выдумывает проблемы при отсутствии данных.
- **Runtime:** durable jobs, leases, retry/backoff, dead-letter, bounded concurrency, DAG dependencies, epoch stop и запрет late completion.
- **Blackboard:** общие объекты и артефакты с типом, версией, автором, provenance и tenant scope.
- **Approvals:** канонический SHA-256 дайджест точного действия, отдельное решение человека, commit по Idempotency-Key и provider receipt.
- **Marketplace:** версии и статусы пакетов, безопасный ZIP, JSON Schema манифеста, разрешения, модерация, Ed25519-подпись доверенного реестра.
- **SDK:** декларативные агенты без исполнения загруженного JS в основном процессе. Нативные пакеты допускаются только через внешнюю OS/VM sandbox.
- **Models:** Ollama или локальный OpenAI-compatible endpoint; rule-based baseline там, где вероятностная модель не нужна. Модель не считается установленной до health check.
- **Billing:** subscriptions, trials, usage events, monthly/per-unit pricing, invoices, entitlement, developer/partner ledger. Это учёт, а не скрытое списание денег.
- **Privacy:** default deny, opt-in, allowlist агрегатов, удаление идентификаторов, k-порог независимых tenant, округление, экспортный аудит.
- **Connectors:** Telegram, WhatsApp, generic webhooks, SMTP, CRM/ERP/1С через явно настроенные HTTP endpoints. Никаких скрытых внешних вызовов.

## Host и developer exchange в 0.2

Локальный client строит снимки разрешённых корней, считает metadata/content hashes, классифицирует процессы и обновляет RAG/business objects. Native fs events дополняются периодическим diff, поэтому добавление, изменение и удаление обрабатываются кросс-платформенно. Публичный snapshot не содержит текста файлов.

Системные действия — зарегистрированные executable/args профили, а не произвольная shell-строка модели. Mutating actions проходят тот же approval/outbox, что и внешние интеграции.

Developer Exchange публикует только privacy-approved агрегаты. Brief включает схемы observation/result и критерии приёмки. Сторонний пакет проходит ZIP/manifest/signature validation, модерацию, director accept и установочный approval. Вознаграждение появляется только из фактически оплаченных счетов.

## Почему не монолитный prompt

24 агента используют общий runtime, но не притворяются одним универсальным ответом LLM. Детерминированные операции — ИНН, суммы, склад, маршруты, дубликаты, anomaly scores, тарификация — проверяются кодом. LLM/VLM подключается для языка и изображений через структурированные схемы, а его результат проходит валидацию и человеческое подтверждение для рискованных действий.

## Офлайн и обновления

После установки Node и получения пакетов/моделей ядро работает без интернета. Каталог и пакеты кэшируются локально. Синхронизация рыночных сигналов, внешние реестры, мессенджеры и оплата требуют сети только в момент использования и явно обозначаются как online-зависимости.

## Границы безопасности

API по умолчанию слушает `127.0.0.1`. Для публикации нужен TLS reverse proxy. Загруженный декларативный manifest — данные, а не код. Любой нативный сторонний код остаётся за пределами доверенного процесса. Дайджест approval подтверждает неизменность действия, но не заменяет аутентификацию человека; provider assertion не заменяет независимую проверку физического результата.
